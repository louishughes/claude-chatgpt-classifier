- **Scoring: an engine `proposal` counts as a match for a key `idea`** (2026-10-28 18:52 UTC). - **Related-chat suggestions without paid labels** (2026-10-28, build agent under the owner's delegated authority, "Use your best judgement and true to the spec and objective"; REL-005, #340; revisitable). (1) A shared web page or video counts as a reason for `related_to` when ten or fewer chats cite it. (2) Distinctive-word overlap (TF-IDF cosine) counts at 0.3, double at 0.5. Both floors were picked before any real scoring and were not tuned on the EVAL-012 key. (3) The embedding cosine is no longer a reason by itself, only extra weight on a pair that already shares something, per "semantic embeddings never replace evidence". (4) A `related_to` pair must rank in the top 3 of both chats, not the top 5 of either. The PC's baseline with the old rules scored 0.727, with 8 of 12 related links inside the key wrong. Recommended default: keep these unless the real re-score drops precision below 0.90.
- **`forked_from` names the direct parent only** (2026-10-28 18:52 UTC; owner delegated the open decisions: "Use your best judgement and true to the spec and objective"; EVAL-012, #240; revisitable). A chat forks from one parent. Two forks of the same chat are `related_to`, not forked from each other, and a fork of a fork is not `forked_from` its grandparent. This is the rule the independent relationship key relkey-v1 used. The shared-node detector now gives each chat one parent (most shared nodes, earliest on a tie), and the copied-prefix detector never adds a second parent. Real score before the fix: precision 0.800 (FAIL), recall 0.408 (`docs/evaluation/EVAL-012_REAL.md`).
- **REL-002 detector defaults** (2026-10-28, build agent under delegated authority; revisitable). (1) "Identical leading messages" (OD-12) compares role plus whitespace-normalised text, not the stored content hash, because that hash includes the create time and a copied chat always has new times. (2) A pasted quote needs a whole paragraph of at least 100 characters; a paragraph found in more than five conversations is treated as boilerplate. (3) If either chat lacks a create time, a fork is proposed as `related_to` with `direction: unknown`, never with a guessed direction. (4) Every detector proposes a `candidate`, including a `references` link from an exact chatgpt.com URL: nothing is auto-accepted. (5) `chatgpt.com/share/…` links are counted as unresolved, because the export doesn't map share IDs to conversations.
- **OPS-004 purge defaults** (2026-10-28, build agent under delegated authority; revisitable; ADR-0010). (1) A purge deletes whole conversations only. (2) The archived copy of each export file that held the chat is deleted whole, although it also holds other chats; their messages stay, and the plan counts how many chats lose their archived original. (3) Tombstones (hashes of the conversation ID and the file) stop a re-import from bringing it back. (4) Running a purge on the owner's real data still needs his explicit go-ahead.
- **RET-001 search index lives in its own file** (2026-10-28, build agent under delegated authority; revisitable). The FTS5 index is `<workspace>/index/search.db`, not a table in `knowledge.db`: it is a rebuildable cache (delete it and the next search refills it), and search changes never need an archive migration. It does hold a copy of message text, so **lawful deletion (DEL tickets) must purge it too** or simply delete and rebuild it. Tokenizer `unicode61 remove_diacritics 2` (case- and accent-insensitive); `exact` mode adds a case-sensitive substring check. One row per message revision, older revisions included.
