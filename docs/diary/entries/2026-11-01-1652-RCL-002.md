### 16:52 — RCL-002: `recall history repeats` finds requests asked again in other chats (#414)

**What:** Louis merged RCL-001 (`recall history find`, #417) by asking the thread to merge it ("You merge."). This is the second ticket of the recall slice. `recall history repeats` looks only at Louis's own messages and groups the ones that ask much the same thing in two or more different chats. It ranks the groups by how many chats they span, and each member shows its date, chat title and IDs. It is local code with no model, so the same history always gives the same groups.

The new module is `src/knowledge_engine/recall/repeats.py`. Each message is cut down to its content words: lower-cased, stemmed, with filler like "the", "how" and "please" removed. Two requests from different chats match when their shared words carry most of the weight of all their words, where rarer words weigh more (IDF-weighted Jaccard, threshold 0.42). Groups merge strongest pair first, and only when every pair of members from different chats still matches. That is complete linkage, and it stops a chain A~B~C from pulling in a C that has little to do with A.

Some messages never count:
- messages with fewer than 3 content words ("continue", "thanks");
- two messages in the same chat, because an edit or a regenerated branch is a revision, not a repeat;
- a re-exported chat, which is one logical chat (IMP-002) and is stored once.

The new synthetic fixture `repeat_requests` has 12 chats:
- 5 planted reworded repeats;
- 4 look-alikes that share most words but ask something else ("write a cover letter for a junior Python developer role" next to "rewrite my CV summary for a junior Python developer role");
- 3 one-word messages;
- one request edited inside a single chat.

**Challenges:**
- **The meaning embedder couldn't tell look-alikes apart.** The first idea was to reuse the local meaning embedder from `ke similar`. On the fixture it scored the cover-letter look-alike at 0.69 against the CV request. The true status-effect rewording scored only 0.66. It counts every shared word, so a long shared phrase swamps the one word that changes the ask.
- **Weighting rare words fixed it.** "cover letter" versus "CV summary" now decides the match. True rewordings score 0.48 and up, and the closest look-alike scores 0.36. The module docstring records this, so the choice can be explained.
- **The threshold is self-tuned, so it isn't trusted yet.** It was set on a fixture the same thread wrote. Whether it holds on real chats is for an independent answer key, made by a separate Claude session that doesn't see the output, as #414 says. Louis doesn't label.
- **Two small development errors.** `dict()` over a SQLAlchemy result failed, and mypy caught a loose type in the CLI. Both were fixed before the tests ran. The tests passed on their first run.

**Known limits:** synonyms are invisible ("GDD" and "design document" share nothing). Words that appear in more than 5% of messages aren't used to *find* candidate pairs, though they still count in the score, so a repeat that shares only very common words is missed. Speed on a full real history hasn't been measured.

**Teach-back (`recall/repeats.py`, chosen by the thread under blanket authority):** This finds the requests I keep making in different chats, with no AI: each message becomes its important words, and two messages match when the words they share carry most of the weight, with rare words counting for more than common ones. Groups only form when every member matches every other member from another chat, so one loose link can't drag in something unrelated. Short messages, edits inside one chat, and re-exported copies never count as repeats.
