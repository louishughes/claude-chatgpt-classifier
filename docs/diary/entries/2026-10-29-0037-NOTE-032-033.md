### 00:37 — NOTE-032 and NOTE-033: open questions checked against the whole chat, and long-chat summaries keep the ending (#373, #374)

**What:** the NOTE-013 step 2 score found two problems. First, the notes listed 23 open questions where the references had 7. Second, 5 of 10 long-chat summaries stopped before the end. Both come from a long chat being digested in parts that can't see each other. Two code checks now run on the merged digest:
- **Questions (NOTE-032):** a question listed twice becomes one that keeps both citations. A question raised in an assistant message ("Want me to draft the letter?") is set aside as `resolved_questions` when a later user message starts by accepting or declining ("Yes, go ahead"). That message must be the user's next one or share a word with the question. The user's words are kept as `resolved_by` evidence and a flag records the change.
- **Ending (NOTE-033):** when a chat has more parts than the four summary sentences, the last part's closing sentence always gets a place. It takes the place of the latest-picked sentence from an earlier part. If the quote check still drops it, the note says "How it ended: not summarised (see part N)."

**Decisions:**
- **No model or prompt change, so no new requests.** Both checks run in code on stored answers. Their versions (`note-032-v1`, `note-033-v1`) are recorded in the flags they write, the same way the NOTE-028 ending rules are. The digest schema version, which is part of every request key, is unchanged on purpose.
- **Only offers are resolved.** A question the user asked can only be answered by the assistant, and whether it was is still the model's reading.
- **"Cites the last part" means a message only the last part has.** Parts share one exchange with their neighbour, so the shared exchange doesn't count as the ending.
- **New digest fields:** `resolved_questions` and `ending_unsummarised`. Both have defaults. The digest is rebuilt from stored answers, not stored itself, so no migration is needed.

**Teach-back (`digest/questions.py`, `reconcile_questions`):** A long chat is digested in pieces, and each piece lists what it leaves open without seeing the rest of the chat. This step looks at the whole chat once more. It joins questions that say the same thing, and it sets aside an assistant's offer when the user later said yes or no to it, keeping the user's reply as proof. A question nobody answered always stays on the list.
