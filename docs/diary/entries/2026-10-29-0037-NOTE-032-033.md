### 00:37 — NOTE-032 and NOTE-033: open questions checked against the whole chat, and long-chat summaries keep the ending (#373, #374)

**What:** the NOTE-013 step 2 score found two problems. First, the notes listed 23 open questions where the references had 7. Second, 5 of 10 long-chat summaries stopped before the end. Both come from a long chat being digested in parts that can't see each other. Two code checks now run on the merged digest:
- **Questions (NOTE-032):** a question listed twice becomes one that keeps both citations. A question raised in an assistant message ("Want me to draft the letter?") is set aside as `resolved_questions` when a later user message starts by accepting or declining ("Yes, go ahead"). That message must be the user's next one or share a word with the question. The user's words are kept as `resolved_by` evidence and a flag records the change.
- **Ending (NOTE-033):** when a chat has more parts than the four summary sentences, the last part's closing sentence always gets a place. It takes the place of the latest-picked sentence from an earlier part. If the quote check still drops it, the note says "How it ended: not summarised (see part N)."

**Decisions:**
- **No model or prompt change, so no new requests.** Both checks run in code on stored answers. Their versions (`note-032-v2`, `note-033-v1`) are recorded in the flags they write, the same way the NOTE-028 ending rules are. The digest schema version, which is part of every request key, is unchanged on purpose.
- **Only offers are resolved.** A question the user asked can only be answered by the assistant, and whether it was is still the model's reading.
- **"Cites the last part" means a message only the last part has.** Parts share one exchange with their neighbour, so the shared exchange doesn't count as the ending.
- **New digest fields:** `resolved_questions` and `ending_unsummarised`. Both have defaults. The digest is rebuilt from stored answers, not stored itself, so no migration is needed.

**Teach-back (`digest/questions.py`, `reconcile_parts`):** A long chat is digested in pieces, and each piece lists what it leaves open without seeing the others. Before the pieces are combined, this step joins the same question coming from two pieces. It also sets aside an assistant's offer when the user clearly said yes or no to it in a later piece, keeping that reply as proof. A hedged "yes, but", a bare "ok" or a reply about something else doesn't count, and a one-piece chat is left alone.

**Clean review:** a reviewer with no context said not to merge yet and gave probe scripts. Its failing probes are now regression tests in `tests/unit/test_digest_questions.py`. The changes, made on the coordinator's calls:
- **Scope.** Reconciling now runs on the parts' answers before they are merged, so before the merge's cap of 8 questions.
  - Questions are joined only when they come from different parts.
  - A question is set aside only when the reply comes in a later part than the question.
  - A one-part chat keeps exactly what the model wrote.
  - The first version also reworked one-part chats, which the ticket ruled out.
- **Blocker 1: the acceptance check was too loose.**
  - A bare "ok", "perfect", "sure" or "thanks" no longer counts as an answer.
  - A reply with "but" or "?" never counts.
  - A reply that adds words must share one with the question, so "No thanks to the chart" answers only the chart offer.
  - When one message held more than one offer, the next reply must name the offer it answers.
  - A reply that isn't the next message must share two words with the question.
- **Blocker 2: different questions were merged.** The comparison now keeps numbers and negations and needs them to match exactly. "Port 8080" and "port 9090" stay apart, and so do "keep" and "not keep". Questions with no key words, or cited from messages of different roles, are never joined.
- **Summary ending.** When the last part's closing sentence fails its quote check, the latest sentence from that part that passes is used before the note says the ending isn't summarised.
- **Flag positions.** Flags now point at positions in `open_questions` or `resolved_questions`.
- **Template version.** `TEMPLATE_VERSION` was not bumped, because `tests/integration/test_rich_note.py` pins `note-001-v2`.
- **One remaining difference on one-part chats:** the digest gains the two empty default fields, while the note is unchanged.
