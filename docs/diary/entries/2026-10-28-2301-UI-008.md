### 23:01 — UI-008: a Timeline page for how decisions moved (#362)

**What:** The PRD's Timeline screen is "current state atop chronological proposals/decisions and supersession links". The engine already worked this out (`ke state`, `ke timeline`), but only on the command line, with IDs and no text. Now `/timeline` lists every stated decision, requirement, preference and rejection in groups: holds now, in conflict, waiting for checks, can't tell when, and replaced later. Each one shows its words, a link to the message it came from, its events in time order, and "replaced by" links that jump to the replacing record on the same page. `?project=ID` narrows it to one project.

**Decisions:**
- The page reads the same projection the notes use (REC-006). It never builds events itself: that stays an explicit `ke timeline --build`, and the empty page says so.
- Records are grouped by status, not one long date list. The question a reader brings is "what holds now?", so that goes first.
- An unknown project ID shows "No such project." rather than an empty page that looks like "no decisions".

**Challenge:** Jinja2 read `group.items` as the dictionary's `.items()` method, not my list. Renamed the key to `records`. Also, my first test borrowed a helper from another test file; with pytest's importlib mode that's fragile, so the helper is copied into the new test.

**Teach-back (`ui/timeline.py`):** It asks the projection where each stated record stands now, and groups them with the current ones first. For each record it loads the words, finds the message its first quote is in, and lists its events oldest first. Links to another record point at that record's own anchor on the page, so following a replacement is one click.
