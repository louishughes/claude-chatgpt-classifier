### 21:29 — NOTE-027: one line per repeated claim

**What:** In the fourth note score, 37 lines were noise, almost all of them the same requirement listed again and again. One note had 28 requirement lines for about 12 ideas. Two things cause it: segments overlap, so one message is extracted twice, and users repeat an ask ("again, 10 questions, no repeats"). The note now shows such records on one line, with every citation and quote kept, plus "Stated N times".

**Why this way:** REC-001 already decides when two records could be the same claim: same type, same person, same direction, same projects, and words that match. It also flags near misses, where the numbers differ or one side says "not". The note reuses that judgement instead of inventing a second one. REC-001's own rule is that the machine never merges records, so this changes only the display, and only inside one chat. The records and their review state stay as they were. Anything wider, such as across chats or in retrieval, still waits for a person to confirm.

**Teach-back (`_collapse` in `documents/rich_note.py`):** It asks the equivalence checker which of a chat's records say the same thing, and puts each such group on one line, placed where the first one was said. That line lists every message where it was said and how many times. "10 questions" and "12 questions" are never put together, even through a third record, because a different number is a different requirement.
