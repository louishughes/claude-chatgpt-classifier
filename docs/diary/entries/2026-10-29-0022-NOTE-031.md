### 00:22 — NOTE-031: chats with no text are never sent for a digest (#370)

**What:** the first 100-chat pass found that `ke digest run` asked for a digest of a chat whose only messages were empty or system ones. The digest must cite at least one quote, so no valid answer could exist, and the request just waited until it timed out. Now the stage checks for user or assistant text first. A chat with none is `no_content`: no request is made, no ledger row is written, and nothing is asked even with egress off. Its note says "Nothing to summarise: the chat has no user or assistant text on its selected path." `ke digest run` counts these chats as `no_content` and still writes their notes.

**Decisions:**
- "Quotable" means any user or assistant message on the active path with non-blank text. These are the same messages the digest is shown. System and tool text is never cited, so it doesn't count.
- No new stored state or migration. `no_content` follows from the chat itself every time, so a re-run gives the same answer and nothing goes stale.
- The run report's `no_content` key appears only when there was such a chat. Existing callers that compare the whole report are unchanged.
- The NOTE-011 note checks accept the no-content lines, just as they accept "not written yet".

**Teach-back (`digest/stage.py`, `has_quotable_text`):** Before asking for a digest, the stage checks whether the chat has anything a summary could quote, which means a user or assistant message with real text. If there's nothing, it asks no one and marks the chat `no_content`, because a question with no possible answer only waits for a timeout. The note then says plainly that there was nothing to summarise, instead of pretending the digest is still to come.
