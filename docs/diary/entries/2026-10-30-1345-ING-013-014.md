### 2026-10-30 13:45 UTC — ING-013/014: note line numbers, note links and the video list, from a clean review (#400, #401)

**What:** the note import (ING-012, #396) had gone into `main` without a final independent review. A reviewer with no history got only the diff, the ticket and the code, and had to back every finding with a script run against the real code. I re-ran those scripts before filing anything. Three small bugs became two tickets:
- *Line numbers one too far.* Python's `splitlines` also breaks a line at a form feed and a few rare Unicode characters that an editor shows inside a line. So a search hit after one of them pointed at the wrong line. Lines now end only at `\r\n`, `\r` or `\n`.
- *`[https://x](https://x)` read as one long wrong URL.* This is how Obsidian writes a link whose label is the address. Notes now split it into two exact links.
- *The video list kept a video after the link was deleted from the note.* It looked at every old version of the note, while the video's own page only looks at the current one. Both now use the current version, and the list's Mentions column counts note links too.

**Decision:** the `[url](url)` fix is switched on for notes only. Chat links use the same finder, and changing what it returns for an old chat would add new link rows the next time that chat is re-imported. That needs its own plan, so it's written down rather than slipped in.

**A clean review of the fix itself.** Before merging, a reviewer with no history checked this fix too. It fed 20,000 random texts to the old and new line splitters and 50,000 to the chat link finder, and got identical results except for the cases the fix meant to change. It found two small gaps, both now fixed. The recorded parser and import versions hadn't changed, so they now say `ing-013-v1`. And `(https://a)(https://b)` was still read as one URL. One known limit is written down: a note imported before this fix keeps its old line numbers, because the same bytes are never read twice. That only matters for a note with a form feed or `[url](url)` in it, and re-importing a changed copy fixes it.

**Decided by Louis:** the review also found that a note quoting a chat stops a later erase of that chat from finishing as "clean", and there's no way to remove a note. That is a product rule, so it went to Louis as a choice. Louis chose to keep the note and say so in the erase report; that is #405.

**Checks:** the six existing note-import tests pass unchanged, plus 10 new ones (one per probe, from both reviews). Full local CI is in the PR.

**Fix attempts:** 1 (one test had the wrong character position in the test itself; the code was right).

**Teach-back (`ui/registries.py`, `list_videos`):** The videos page lists every YouTube video found in chats or in imported notes.
