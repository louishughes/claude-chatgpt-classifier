### 13:30 — OPS-011: test everything with a double-click (#397)

**What:** Louis asked how to test everything. The first answer was a list of PowerShell commands. He said he needed something simpler than typing commands, so now there are three files in the project folder to double-click:
- `TEST_EVERYTHING.bat` sets up Python the first time, then runs every check CI runs, everyday and nightly. It opens a report in the browser: a green or red line per area (tidiness, types, privacy guard, all tests, scorecard, same-answer-every-time, whole journey), what each area proves, and what to do if it's red, with the end of the log just under it.
- `OPEN_DEMO_DASHBOARD.bat` imports five made-up chats into a separate demo workspace and opens the dashboard on them.
- `OPEN_DASHBOARD.bat` opens the dashboard on his real chats.

`docs/TESTING.md` has the click-through checklist: what to click on each page, and what you should see there.

**Decisions:**
- The report reuses the CI module's list of checks and its key-stripping, rather than listing the commands a second time. That way "green on the button" and "green in CI" can't drift apart, and no API key ever reaches a check. A test fails if CI gains a step that the report has no plain words for.
- The demo uses its own workspace (`workspace\demo`), so synthetic chats never land in the real archive.
- The checklist's expected values (5 chats, 3 hits for "shed", 1 video with 2 mentions, "Nothing new" on a re-import) were read off the real demo dashboard, not written from memory.

**Challenge:** while writing the checklist, a scripted browser test of the Import page was refused with "not from this app". The form token was fine: the same form sent by hand worked. The script had clicked a different submit button on the page. The page was right and the test script was wrong.

**Teach-back (`devtools/test_report.py`):** It runs each check CI runs, one after another, with every API key removed, and saves each one's output to its own log file. A check that fails doesn't stop the others, so one run shows everything that's wrong. It then writes a web page with one green or red line per area, in plain words, and opens it in the browser.

**Review:** a clean reviewer, given only the acceptance conditions, ran the demo checklist against a real demo dashboard. All 11 steps matched, and it gave a PASS with no must-fix items. Fixed from its should-fix list:
- The double-click no longer stops when there's no internet, as long as the project is already installed.
- The checks run in UTF-8 mode, so a "→" in some output can't turn a Windows check red for no reason.
- The YouTube access token is stripped too, since its name matched none of the old key patterns.
- The demo stops with a clear message if its import fails.
- Times can't read "1m 60s".
- A miscount in the guide is fixed ("two parts" when the table had three).

Kept as it is: the demo lives in `workspace\demo`, not a separate top-level folder, because the project's rule says nothing goes next to the project folder.
