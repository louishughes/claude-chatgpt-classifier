### 14:11 — RCL-001: a read-only `recall` command, and the plan behind it (#413)

**What:** Louis saw a post suggesting that developers build a small CLI for their project, so that AI agents stop re-reading the same files and re-typing the same commands. The thread started building that: a `bin/agent-cli` for this repo. It mined the session logs and diary for repeated commands, and the same lint, type and test commands showed up about 80 times. Before any code was written, Louis redirected. What he really wanted was the same idea pointed at his ChatGPT history instead of at the repo: a `recall` command that answers "what did I decide?", "what do I keep asking?" and "where did I talk about X?".

The thread mapped his write-up onto what the classifier already does. Most of it was already built: original messages kept as the source of truth, FTS5 word search, local meaning search, assistant suggestions kept apart from the user's decisions, a decision timeline, and conflicts that stay visible. The genuinely new piece is "history repeats". The plan (a Claude Doc) became four tickets, filed as GitHub Issues #413 to #416:
- RCL-001: the `recall` front door and `history find`;
- RCL-002: `history repeats`, with no AI;
- RCL-003: `projects show`;
- RCL-004: `decisions history`.

This entry is RCL-001. `recall` is a second console script in the same package (`src/knowledge_engine/recall/cli.py`), with no new dependencies. `recall history find` calls the very same functions as `ke search` and `ke similar`, then adds each hit's chat title and date. Meaning hits, which have no highlighted snippet, get the start of the message instead. `--json` works anywhere on the line and prints ke's usual JSON envelope. Asking for date or speaker filters with `--meaning` is refused, because meaning search can't apply them and quietly ignoring them would be worse.

**Louis's decisions (2026-11-01):**
- **Recall over the agent-helper CLI.** The agent CLI is paused, not dropped.
- **Both audiences, agents first.** Every command gets a short `--json`, an `AGENTS.md` line tells agents to try `recall` first, and readable text stays the default for a person.
- **The game-dev version is an example, not a separate product.** Later, "category modules" could be generated from the classifier's categories and subcategories: recall filtered to one category, with its subcategories as sections. Anything subject-specific, like a mechanic library, goes through the reviewed vocabulary.
- **The knowledge engine stays deterministic.** Any AI reasoning sits on top as a separate layer, and its output is always a suggestion, never a decision.

**Challenges:**
- **The goal moved mid-thread.** The CLI was paused before any code existed, so nothing was thrown away.
- **GitHub search needed `is:issue`** in the query before it would answer.

**Teach-back (`recall/cli.py`, chosen by the thread under blanket authority):** `recall` is a small, read-only command for asking my own chat history questions. It reuses the exact search functions behind `ke search`, so the two can never disagree, and it only adds what a person needs: the chat's title and the message's date. Every hit names its chat and message ID, so you can always go back to the original instead of trusting a summary.
