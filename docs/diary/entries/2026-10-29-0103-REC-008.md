### 01:03 — REC-008: working through contradictions and record links (#379)

**What:** The second spec audit (a fresh reviewer with no context) found that contradictions were detected but could never be reviewed. `ke reconcile` stored each one as "unresolved", and nothing could change that, so a record flagged "conflicted" stayed flagged in `ke state`, the timeline and answers for good. The PRD's journey 8 is "work through unresolved contradictions". The same was true of record links (creates, references, elaborates and so on): they were proposed, but no one could accept or reject them.

There are now two command groups:
- `ke conflicts list [--state]` and `ke conflicts review KCF dismiss|resolve|reopen --reviewer --note`.
- `ke links list [--state] [--record]` and `ke links review KRL accept|reject --reviewer [--note]`.

Both lists show IDs, kinds, scope, evidence revision IDs and the full review history, never the chats' words.

**Decisions:**
- A conflict review always needs a reason (`--note`), because the store already required one. A link review's note is optional, matching `ke duplicates review`.
- "Reopen" is the person's word for going back to unresolved. It brings the "conflicted" flag back.
- An unknown ID, or a review that changes nothing, is a usage error (exit 2), and the ID asked for is never repeated back.
- No new store code: both review functions already existed (REC-002 and REC-003). This ticket only gives them a door.

**Challenge:** The rules fixture's detectors propose no record link at all, so the test stores one by hand between the first pair of records the link rules allow. A rejected link then drops out of the notes, and `ke walk` only follows it with `--include-closed`.

**Teach-back (`ke conflicts` in `cli/main.py`):** It lists every stored contradiction between two records, with the reviews so far. A reviewer can dismiss it (not a real conflict), resolve it, or reopen it, always saying why. The current-state view reads those reviews, so a dismissed conflict stops flagging its two records as "conflicted".

**Review:** a clean reviewer with only the acceptance conditions gave a PASS with two should-fix items, and both are fixed. The unknown-link case now proves the ID isn't echoed back, and a refused link review (no change, or a blank reviewer) is now tested. `--state` also gained help text.
