Now `ke search`, `GET /api/v1/search` and (later, UI-009) the search page take `--since`/`--until` (UTC days, both included), `--role` and `--term` (an approved taxonomy term or project ID). Filters combine.

**Decisions:**
- A term the vocabulary doesn't approve is refused (`unknown_term`), not ignored. Ignoring it would quietly search everything.
- "About a term" uses the same rule as the topic master: labels in force, a reviewer's choice over the machine's. So a filtered search and a topic note agree.
- Messages with no time can't be placed in a date range. They're left out, but the result says how many (`undated_left_out`), so "no hits" never hides them.
- The index file gained the message time; its version went up, so old index files are dropped and rebuilt on the next search. The index is a cache, so that costs nothing but a rebuild.

**Challenge:** Python's `date.fromisoformat` happily reads `20240101` and week dates. The filter only accepts the plain `YYYY-MM-DD` form, so a typo is an error, not a different day. API errors also don't repeat what was sent, which matches the rest of the API.

**Teach-back (`retrieval/filters.py`):** It turns "since, until, speaker, term" into a checked filter before the search runs, and refuses anything it can't honour. For a term, it finds every message inside a segment whose labels in force carry that ID. The word index then keeps only hits that pass all the filters, and counts the undated ones a date filter left out.
