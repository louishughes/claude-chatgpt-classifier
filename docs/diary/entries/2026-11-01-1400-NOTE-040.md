# 2026-11-01 14:00 UTC — NOTE-040: one keyword per idea (#411)

**What:** After reading the independent review, Louis asked: "Can we get rid of the repeat and filler words?" The note's Keywords line now goes through a new `shown_keywords()` step. It shows each idea once ("Cedar Boards" and "cedar boards" are the same keyword), drops a word that was only ever said as part of a longer keyword ("boards" when it was always "cedar boards" or "pine boards"), and drops title words the chat never talks about again (the title is already the note's heading). About fifteen more chat filler words ("prefer", "options", "answer", "reply", "thanks"...) can no longer become keywords at all.

**Why this way:** the existing tests pin the full candidate list, including title words like "Unreal" and "Engine" next to "Unreal Engine", and the project rule is that agents don't change tests without Louis's approval. So the candidate list stays exactly as it was, with every reason attached, and the tidying happens only where the note picks what to show. That also keeps the "why is this a keyword?" trail inspectable. Approved taxonomy terms are never hidden.

**Challenge:** the first version of the new tests passed straight away, which was suspicious. Printing the candidates showed why: two of the tests checked words the old code had already removed, so they proved nothing. The fixtures were rewritten so each test first shows the repeat really is in the candidate list, then that the note leaves it out.

**Before and after (synthetic chat):** `bed, raised, Timber, cedar, pine; Synthetic; boards, Cedar boards; cedar bed, deep` became `bed, Timber, cedar, pine; boards, cedar boards; cedar bed, deep`.

**Not done:** adjectives like "deep" still get through; telling a subject word from a describing word needs a part-of-speech tagger, which is a bigger decision. Whether this helps on real chats has to be scored on Louis's PC by a session that didn't write it.

**Teach-back** (`documents/keywords.py`, `shown_keywords`, picked by the thread): The keyword step finds every candidate word and keeps a reason for each. Before a note shows them, `shown_keywords` walks the list best-first and skips anything that repeats an idea already shown: the same word in another case or plural, a word only ever said inside a longer keyword, or a title word the chat never repeats. The full list stays untouched, so you can always see what was hidden and why.

**Talking points:**
- "Fix the presentation, not the evidence: the full keyword list and its reasons stay, the note just stops repeating itself."
- "My first tests passed instantly, and that was the bug: they tested words that were already gone."
- "Rules I can't change without asking (the tests) shaped where the fix went."
