### 22:49 — DOC-007 and DOC-008: a project bundle you can hand over, and check without trusting it

**What:** `ke bundle export PROJECT --to FILE.zip` writes one approved project as a ZIP. It holds a manifest (format, project, taxonomy and engine versions, counts, and a SHA-256 for every member), the project master, the knowledge note of each chat it draws on, and `records.jsonl`: each record with its standing and the exact quoted words behind it. Full transcripts are left out unless `--with-transcripts` is given. `ke bundle verify` re-checks the manifest, every hash, every member name and size, and every quote against its own hash. `ke bundle show` counts records by type and status, without showing any text.

**Why this way:** The spec asks for project bundles that can be exported and imported. Importing records into another workspace would skip that workspace's evidence checks, so a bundle is only ever read, and it is treated as untrusted input. Member names go through the importer's own `safe_member_name`, and the limits are the OPS-002 ones. The ZIP is byte-identical on a rerun (fixed order and timestamp, manifest first), so its hash says whether anything changed. Notes keep their vault paths, so the links between them still work when the bundle is unzipped into Obsidian.

**Teach-back (`documents/bundle.py`):** It gathers one approved project's master note, its chats' notes and its records, with the words each record quotes, and writes them into a ZIP whose manifest lists a fingerprint of every file. Checking a bundle re-fingerprints every file and every quote, and refuses odd file names or oversized files. Nothing in a bundle is ever loaded into the database, because its claims were checked against someone else's chats.
