### 22:49 — DOC-007 and DOC-008: a project bundle you can hand over, and check without trusting it

**What:** `ke bundle export PROJECT --to FILE.zip` writes one approved project as a ZIP. It holds a manifest (format, project, taxonomy and engine versions, counts, and a SHA-256 for every member), the project master, the knowledge note of each chat it draws on, and `records.jsonl`: each record with its standing and the exact quoted words behind it. Full transcripts are left out unless `--with-transcripts` is given. `ke bundle verify` re-checks the manifest, every hash, every member name and size, and every quote against its own hash. `ke bundle show` counts records by type and status, without showing any text.

**Why this way:** The spec asks for project bundles that can be exported and imported. Importing records into another workspace would skip that workspace's evidence checks, so a bundle is only ever read, and it is treated as untrusted input. Member names go through the importer's own `safe_member_name`, and the limits are the OPS-002 ones. The ZIP is byte-identical on a rerun (fixed order and timestamp, manifest first), so its hash says whether anything changed. Notes keep their vault paths, so the links between them still work when the bundle is unzipped into Obsidian.

**Teach-back (`documents/bundle.py`):** It gathers one approved project's master note, its chats' notes and its records, with the words each record quotes, and writes them into a ZIP whose manifest lists a fingerprint of every file. Checking a bundle re-fingerprints every file and every quote, and refuses odd file names or oversized files. Nothing in a bundle is ever loaded into the database, because its claims were checked against someone else's chats.

Fix attempts: 2. The first was mypy: a reused variable name in the CLI handler. The second was the clean review fixes. During those, a test showed that the unpacked-total check ran before the per-member size check, so names and declared sizes are now checked before anything is read.

**Clean review:** a reviewer with no context, given only the two tickets' test conditions, found two blockers.
- No total size limit, and every member's bytes were held in memory. A tiny ZIP could exhaust memory.
- Damaged or misshapen input crashed `verify` and `show`: a bad CRC, corrupt deflate data, an array manifest, or `members` given as a list.

It also found three should-fix points:
- Problems printed member paths, which hold chat titles.
- A bundle with no `records.jsonl` passed.
- The export's fixed `.partial` name followed a planted link and was left behind on failure.

All of these are fixed, each with a test:
- Members are hashed as a stream, and only the manifest and records are kept. The unpacked total is held to the OPS-002 `max_source_file_bytes`.
- Damaged, encrypted and unsupported members become named problems.
- Problems name a member by a short hash of its path (`member_label`).
- `records.jsonl` is required.
- The export writes to a fresh `mkstemp` name and removes it on failure.

The quote nit is fixed too. A quote that isn't an object, or that has neither text nor a problem, now reports a problem. `show` counts only known record types and statuses, and anything else is counted as "other". A `bundle show` non-zero test was added.

Two of this PR's own new tampering assertions now expect the hashed label instead of the path. They are not existing tests from main.

Nits left as they are:
- Picking the taxonomy when two versions share a timestamp.
- Symlink mode bits inside a ZIP, which are harmless because nothing is extracted.
