### 01:14 — UI-010: one page per image, listing every message that uses it (#384)

**What:** The second spec audit found that image identity was stored separately from where each image is used, as CLAUDE.md §2A asks, but nothing showed it. The only image route was `/media/<sha>`, which serves the raw bytes. Now:
- `/assets/<asset_id>` shows the image once, then lists every message that uses it (chat, sender, time), each linking to the exact message. Each row also shows its own availability, with the reason when the file is missing.
- Every image on a chat page has an "Every message using this file" link to that page.
- `ke inspect asset_…` prints the same list as IDs and places: conversation ID, message anchor and availability. It never prints titles or text.

**Decisions:**
- If the same bytes arrive under a different file ID, they stay a separate asset, as ADR-0004 says. The page notes that "the same bytes are also stored as N other files" rather than merging the two.
- A file that no export has supplied still gets a page, because its messages are real. The page says the file isn't there and shows no picture and no invented path.
- An unknown ID gives a 404, or exit 2 on the command line, and the ID isn't repeated back.

**Challenge:** The UI's generic one-row page helper uses the record's display name as the template variable, so "image or file" couldn't be passed through it. The asset route renders its page directly instead.

**Teach-back (`ui/registries.py`, `asset_page`):** It looks up one logical file from the export and every message that uses it, counting each message once in its newest version, oldest message first. For each occurrence it finds the chat and the message anchor, so every row is one click from the message itself. It also counts the chats, and notes any other file with identical bytes without merging them.

**Review:** a clean reviewer with only the acceptance conditions gave a FAIL with one must-fix. A message that a later export edited was counted twice, because each stored revision of a message became its own row ("used in 5 messages" for 3). Re-exporting the whole history is the normal case, so the page now counts each message once, in its newest revision, which is the same rule the chat page uses. If an image appears only in an older version of a message, that is shown as a separate count rather than dropped. A new test re-imports with one edited message; it fails on the old code and passes now. The other should-fix items are also done: the missing-image test now checks the reason and that every link opens, and `ke inspect` is tested on a missing file (no file IDs or paths). A re-review passed; its one remaining should-fix (a use whose message row is missing would vanish instead of showing "message not found") is fixed too.
