### 22:58 — UI-007: an Ask page in the browser (#361)

**What:** The PRD's Search/Q&A screen wants "cited evidence chips; show retrieval method, filters and unknown/conflict outcomes". `ke ask` and the API could answer with citations, but the browser couldn't. Now `/ask` (in the sidebar under "Your archive") answers a question from your chats: each sentence ends in numbered chips, each chip opens the exact message it cites, a Sources list names each message, and "How it looked" says which search route ran and why.

**Decisions:**
- The page calls the same `answer` function as `ke ask`. A second copy for the browser could drift and say something the audited path wouldn't.
- When the planned route finds nothing and the answer falls back to searching messages, the page says so instead of showing only the final route.
- "No AI model called" is only printed when the writer really is the local extractive one.

**Teach-back (`ui/ask.py`):** It brings the word and meaning indexes up to date, then runs the normal answer service for the question. It numbers each citation and looks up which chat and message each one points to, so the page can link straight there. If nothing qualifies, the page shows the service's own "I can't find this in your chats" and no sources.
