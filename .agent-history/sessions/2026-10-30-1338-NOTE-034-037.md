### 13:38 — NOTE-034: chat status decided once, for the whole chat; NOTE-037 blocked on existing tests (#392, #395)

**What:** the NOTE-013 pass 1 score had status right in only 3 of 10 notes, wrong in both directions. Two checks used to run one after the other on the merged digest. `settle_status` set the status from the ending (NOTE-019). Then `questions_keep_open` could flip it back because of an open question (NOTE-028). Three faults came out of that, and the synthetic fixtures reproduce each one on the old code:
- **Finished but marked open.** A chat ends with a result and "Want me to make a green version too?". The model lists that offer as an open question, plus an earlier question. The earlier question switched off the offer's exemption, so the offer itself flipped the chat to open.
- **Open but marked settled.** In a long chat, the parts listed more than 8 open questions. The merge keeps the first 8, which are the earliest parts' questions. The last part's question about the ending was cut before the status check saw it.
- **Two contradicting flags.** With an offer ending and a question in the last exchange, the status went open → settled → open, with two flags and no net change.

Now `digest/status.py` `decide_status` runs once, after the parts are merged and their questions reconciled (NOTE-032). It decides from the ending plus the open questions still open after reconciling. Those come from every part and are taken before the merge's cap. The rule table is in the module docstring. Only a question that cites the last exchange (the user's last message or later) can keep a chat open. With an offer ending, each question is judged on its own, and a question citing only the closing offer doesn't count. A change makes one flag, and the new status cites the message that decided it. `settle_status` and `questions_keep_open` are gone from `digest/ending.py`. `_status_item` is now the public `status_item`, because `status.py` uses it too.

**Decisions (delegated; revisitable):**
- **Rule version `note-034-v1`.** The status rules and the ending rules are one rule set, so `ENDING_VERSION` is bumped and `STATUS_VERSION` is the same value. The prompt and schema versions are unchanged. Stored answers are re-checked in code, and nothing is asked again.
- **"Open with nothing open" is not turned into settled.** I considered the mirror of NOTE-028: when the model says open, the assistant spoke last and no question is in the last exchange, the chat is settled. The existing test `test_no_rule_leaves_the_models_reading_alone` pins the opposite (model says open, no rule, so it stays open). So row 6 keeps the model's reading, and that test still passes.

**Teach-back (`digest/status.py`, `decide_status`):** After a long chat's pieces are joined and their open questions are checked against each other, this decides the chat's status once, for the whole chat. If that gives a different answer from the model's, it changes the status, cites the message that decided it, and leaves one flag saying why.
