**What:** NOTE-013 pass 1 found digest items backed by a quote like "I". `digest/contract.py` has a new module-level helper, `is_trivial_quote`. A quote is refused when it has fewer than `MIN_QUOTE_CONTENT_WORDS` (2) content words **and** fewer than `MIN_QUOTE_CHARS` (12) characters. Stop words don't count as content words; they are `STOP_WORDS` from `reconciliation/equivalence.py`, which `digest/questions.py` already uses. One distinctive token still passes:
- a link (`https://…`, `www.…`);
- a token with a digit next to a letter or a unit sign: `v2.3`, `5GB`, `x86_64`, `10%`, `£40`.

A bare number like "8080" is refused when it stands alone, because a number with no unit is as common as "yes". "Use port 8080" passes, since "port" and "8080" are two content words.

`_resolve_item` runs this check after the quote is found, so a refused quote sinks its item exactly as a missing quote does. The flag reason is `quote too short to prove anything (note-037-v1)`. A quote that is short **and** missing still says "quote not found", because that is the real fault.

**Decisions (delegated; revisitable):**
- **The new version is `QUOTE_CHECK_VERSION = "note-037-v1"`, kept out of the request key.** The digest had no separate validation version. `DIGEST_SCHEMA_VERSION` and `PROMPT_VERSION` are both part of the stage key, so bumping either one would ask every chat again. - **"A number with a unit" means a digit next to a letter or a unit sign within one token.** "5 GB" written with a space is already two content words, so it passes anyway.
