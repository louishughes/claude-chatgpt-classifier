# NOTE-035/036: Decisions from the user's choices; profile words out of keywords

**When:** 2026-10-29 05:15 UTC, paused by the owner, finished 2026-10-30. **Tickets:** NOTE-035 (#393), NOTE-036 (#394). **Found by:** NOTE-013 pass 1 score.

**What changed:**
- **NOTE-035** (`documents/rich_note.py`, `_user_choice`): a requirement or preference the **user** holds with **explicit** acceptance, phrased as a choice ("I'll go with", "let's use", "we're doing", "decided to", "settled on"), now shows under Decisions, once, not also under Requirements.
  - Assistant records never move, however they are worded, so a suggestion still never becomes a decision.
  - A conditional "if it fits" stays a preference.
- **NOTE-036** (`documents/keywords.py`): keyword candidates leave out the `user_editable_context` profile and any user paragraph that repeats a profile paragraph, compared case- and spacing-blind. The same words in a real sentence still count. `KEYWORDS_VERSION` is now `note-007-v2`.

**Checked, not changed:** the ticket asked about "the user asked for X" being filed as an assistant suggestion. That comes from NOTE-005 rule 1: a user decision that quotes only assistant words is demoted. That is the guard against putting words in the user's mouth, so I kept it. The fix belongs in the extraction prompt, which should quote the user's own request, and that is a separate change.

**Teach-back (`_user_choice`):** It looks at the user's own preferences and requirements, and lifts the ones that pick something ("I'll go with the oak") into Decisions. It only does that when the user said it plainly themselves, never for something the assistant said. A hedged "if it fits" stays a preference.
